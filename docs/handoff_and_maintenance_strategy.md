# TTFS Cool Schools Dashboard: Deployment & Lifecycle Handoff Strategy

## 1. Current Situation & The "22-Month Window"
The initial expectation for the TTFS Cool Schools Dashboard was to serve as an end-of-project data visualization tool, showcasing baseline numbers and post-baseline studies at the conclusion of the grant cycle. 

However, the dashboard is now positioned to go live at **Month 2**, leaving a **22-month window** for iterative development, data collection, and UI polishing. This accelerated timeline requires a clear division of responsibilities to ensure the UTRGV team can focus on data science and development, while Texas Trees Foundation (TTF) handles the operational hosting and user support.

## 2. The Handoff Mandate
In accordance with the project's governance rules, the dashboard must be highly portable and designed to avoid vendor lock-in. 
* **UTRGV Role:** Product Developers & Data Scientists.
* **TTF Role:** Product Owners, Hosts, and Primary Support.

To achieve this cleanly, the UTRGV team will not host the final production application on UTRGV servers, nor will they manage active passwords or user PII (Personally Identifiable Information). Doing so would violate FERPA/COPPA compliance policies and create an unsustainable 10-year IT support burden.

## 3. Recommended Hosting Architecture
### Phase 1: Static Handoff (Current State)
Right now, the dashboard is a collection of static web files (HTML, CSS, JS). It requires no databases or authentication servers.
* **Handoff Method:** The UTRGV team can provide the code repository (via GitHub or a physical flash drive) directly to TTF's IT staff.
* **Hosting:** TTF can host this on their existing infrastructure (e.g., as a subdomain like `dashboard.texastrees.org`). Static hosting costs are negligible ($0 - $10/month) and scale infinitely.

### Phase 2: Dynamic Scaling (Future State)
If the project scales to 14 schools (approx. 2,800 total users) with dynamic features like photo uploads, teacher logins, or student data entries, a backend will be required.
* **Infrastructure:** We recommend using **Firebase** (Google's app platform) or a similar portable service. Firebase handles secure authentication, database storage, and file hosting.
* **Estimated Costs:** ~$50/month for active bandwidth, database reads/writes, and storage once fully scaled.

## 4. The "Agency Model" Handoff (Recommended for Backend)
You noted a very valid concern: expecting a non-technical client to set up a cloud architecture (Firebase) from scratch is often a recipe for delays and frustration. 

Instead, the UTRGV team can operate like a web development agency:
1. **UTRGV Builds It:** UTRGV creates the Firebase project, connects the dashboard, and gets it completely live and functional. (Firebase has a generous free tier, so UTRGV will likely pay $0 during this development phase).
2. **Transfer of Ownership:** When the project is ready for the official handoff, UTRGV simply invites TTF’s IT admin (or their subcontractor) to the Firebase project as an "Owner". 
3. **Billing Handoff:** TTF enters their credit card to take over the billing account. Once their billing is attached, UTRGV removes their own administrative access.
4. **Why this is better:** TTF gets a turnkey, fully functional product without having to navigate technical setup, but they still ultimately own the data and the liability.

## 5. Division of Responsibilities (The Next 22 Months)

### Texas Trees Foundation (TTF) Responsibilities
1. **Server Hosting & Billing:** Provide the web hosting environment, domain name (`texastrees.org`), and pay any associated cloud infrastructure costs (e.g., Firebase).
2. **Data Ownership:** Act as the legal custodian for any dynamic user data generated by students or teachers.
3. **Tier 1 IT Support (Helpdesk):** 
   - Handle password resets.
   - Answer basic "How do I use this?" questions.
   - Manage user account provisioning for the 14 schools.
4. **Deployment:** Work with UTRGV to pull in new code updates from the GitHub repository to the live servers.

### UTRGV Team Responsibilities
1. **Iterative Development:** Continue polishing the UI, building new modules (e.g., Soil Moisture, Avian Acoustics), and refining data visualizations over the remaining 22 months.
2. **Data Collection & Analysis:** Ensure the dashboard accurately reflects incoming research data and post-baseline studies.
3. **Tier 2 Technical Support:** 
   - Fix code bugs or broken features on the dashboard.
   - Resolve complex data pipeline issues.
   - Provide technical documentation for new features.
   - *Note: UTRGV does not handle password resets or individual user complaints.*

## 6. Next Steps for Implementation
1. **Present this strategy to TTF:** Ensure all stakeholders agree on the division of labor, particularly the Tier 1 Support and Hosting requirements.
2. **Establish the GitHub Pipeline:** Set up TTF's IT team with access to the `ttfs-cool-schools-dashboard` repository so they can pull the latest updates whenever the UTRGV team finishes a new module.
3. **Determine Backend Needs:** Decide if the Month 2 launch requires user logins and uploads. If yes, UTRGV will create a free-tier Firebase project to build and test the architecture, with the explicit agreement that TTF takes over billing ownership at launch.
